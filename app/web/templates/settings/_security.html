Audit log

Every entry is hash-chained (each links to the previous one's hash), so altering or removing an entry breaks the chain from that point on — see Audit and the wiki page "Architecture" for how that works and what it doesn't protect against.

Leave empty to keep every entry forever (the default). Otherwise, entries older than this are permanently deleted once a day — the chain's most recent entries and its ability to verify what remains are unaffected, since only the oldest end is ever pruned.

Dashboard trends

A background job records one daily snapshot of fleet-wide counts (online/offline machines, pending updates, ...) for the trend chart(s) on the Dashboard. This only controls how long those snapshots are kept — it doesn't affect the live counts themselves.

Leave empty to keep every snapshot forever. Defaults to 90 days.

Update run history

Each entry on a machine's Updates tab (the apt/flatpak/snap output from one run) is stored in full — this only controls how long those stored runs are kept, not whether updates themselves run. On a large fleet with recurring scheduled updates (see Scheduling) this table can otherwise grow without bound. The fact that an update was triggered stays in the audit log regardless of this setting — only the stored run record/output is purged.

Leave empty to keep every run forever. Defaults to 90 days.

Monitoring history

A CPU/RAM/disk-usage sample is stored for every machine on the Monitoring tab's own cadence (MONITORING_INTERVAL_SECONDS, 2 minutes by default) — this only controls how long those samples are kept, not how often they're taken. A single machine can override this instance-wide default on its own Settings tab.

Leave empty to keep every sample forever. Defaults to 90 days.
